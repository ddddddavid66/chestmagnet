## A/B 初筛：不合入查箱改动

- **结构空槽复用：**使用临时构建，同一进程一个预热组、五组交错开关；每侧每场景每组 40 次调用、实收 120 件且来源为空。原版单桶最后一槽的结构热路径，服务端单调用 p95（µs）：关 **590 / 713 / 906 / 490 / 488**，开 **427 / 941 / 209 / 379 / 161**。开胜 4/5，组 p95 中位数 590 → 379 µs。这只是反射驱动的热区块单桶初筛，未使用正式任务的时间片，不代表真实收完时间或帧时间。两个附近夹具均不走改动代码，数值波动不计作收益。
- **附近队列：**用初版正式 JAR（SHA-256 见初版记录）另跑同类短夹具，JFR 有 21 条分配采样栈进入 `Engine.work`，没有采到反复删插的 LinkedHashMap 节点／迭代器。样本少，不能排除密集世界里存在此开销；本轮没有证据支持换队列。
- 本轮仅一个结构热微场景确认局部收益；只改结构空槽最多影响热／冷两个场景，达不到 **3/4** 验收线。未进行完整四场景验收、冷区块双箱性能、客户端帧时间或稳定堆占用对照；不报整体提速。临时候选未进入交付包，查箱代码、范围、预算和票据额度均保留。

## 复现

- 正式构建：`gradlew.bat build --offline -Dnet.minecraftforge.gradle.check.certs=false -PforgeVersion=47.2.18`（依赖已缓存时）。打包前确认没有加 `-Pverification`。
- 分离测试辅助 JAR 后运行 `python scripts/qa128.py <case> --magnet <正式JAR> --compass <指南针JAR>`。可用 `enhance159`、`enhance159-sync`、`enhance`、`edited`、`edited-fallback`、`original`、`custom`、`minimal`。原始关键日志见交付包的 `evidence/`。
