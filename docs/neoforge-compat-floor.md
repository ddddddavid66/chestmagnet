# 1.2.8 NeoForge 降门槛实测

Minecraft **1.21.1**、Java **21**。磁铁单装由 **NeoForge 21.1.230** 降至 **21.1.1**：用 21.1.1 编译通过，正式候选 JAR 在独立服务端收取、部分接收与旧数据迁移均通过；在真实客户端验证四键注册、实际到账、配置页和历史。复用现有收取逻辑，不修改网络协议、存档或已发布的 JAR。

## 不能再降的已知原因

- RS 2.0.0–2.0.3 没有磁铁所需的能耗判定接口，未用猜测或跳过扣电来降版。超越维度 0.7.x 缺当前使用的物品索引，不改成全仓扫描。
- Lootr 更老的候选缺开箱权限接口；Quark 4.1-473 实际未提供板条箱能力，4.1-474 仍没有对应注册，改用 4.1-475。
- Aquamirae 7.2.0 在独立服加载结构时访问尚未加载的配置，改用修复后的 7.2.1 和它要求的 Fragmentum 2.4.4。
- FTB 的旧单参数和当前双参数候选展开接口，在专用服过滤烟测中都会进入客户端类。撤回单参数桥，不宣传过滤兼容；保留原行为与已支持的普通持有检测，不改变任务匹配或扣除规则。

## 复现与证据

用 Java 21 和 Git 工作区里的脚本运行，依赖发行文件及 SHA-256 见[锁定表](neoforge-upstream-lock.json)。原始 1.2.8 的结果与本轮分开保留。

- 编译：`gradlew.bat compileJava -PneoForgeVersion=21.1.1`；构建：`gradlew.bat dist neoforgeQaJar -PdistDirectory=dist/compat-floor`。
- 服务端先用 `python scripts/qa-neoforge.py minimal --neoforge 21.1.1`。联动使用既有用例和 `--swap 当前键=旧版锁定键`，客户端用 `--neoforge` 选加载器、`--mods` 选锁定依赖。
- 主要日志目录位于工作区 `run/neoforge-qa/`：本体 `minimal-1794816838879498400`、`client-2-1794816762272975400`；储物组合 `lowest-1794816860862710000`；超越维度客户端 `client-2-1794816724799858200`；锁箱 `locked-1794816866740436400`；FTB 旧／新版 `quests-1794816776053175500`、`quests-1794816804436686400`。
