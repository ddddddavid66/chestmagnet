FTB 不使用历史记录。无法可靠展开的特殊过滤器仍走原生流程；FTB 或其他模组独立执行的原版 NBT 策略以及旧任务进度不变。本次未重复测试整套共振存储组合，也未用现有存档做迁移。保存验证使用玩家序列化后重新加载，不冒充人工重登。

最终正式客户端的 67 个 FTB 检测片段：p50 **0.221 ms**、p95 **6.314 ms**、最大 **20.569 ms**。包含第三方首次调用和进度更新；0.5 ms 是软时间片，不能抢占原生调用。短时帧时间开/关受预热影响，不能解释为提速。

## 查箱 A/B

Forge 47.2.18，隔离服务端同一世界，开关同一验证构建中的临时候选，预热后 3 组交错 A/B，每组每场景 40 次；每批实际收取 120 件。下表为每组主线程调用 p95（µs）。这是热区块单轮微基准，**不代表整座结构的实时时间或冷加载**。

| 场景 | 原逻辑 p95 | 候选 p95 | 决定 |
| --- | --- | --- | --- |
| 附近静止启动 | 423 / 105 / 89 | 140 / 129 / 80 | 不稳定，撤回 |
| 附近移动后重新进入扫描 | 127 / 92 / 87 | 102 / 94 / 78 | 差异小，撤回 |
| 热结构，原版桶末槽 | 410 / 385 / 420 | 339 / 312 / 221 | 此夹具 CPU 开销下降；未完成冷区块、跨区块双箱及真实任务延迟对照，不合入 |

发行版保留原查箱逻辑、范围和票据额度。没有确认密集实体查询尖刺或复现冷区块双箱饥饿，未改对应调度。发行包附原始结果和候选差异。
