# 宝箱磁铁 1.2.8 · Lootr 修订

基线：GitHub 已发布的 1.2.8（`d74ca02`）。JAR 仍显示 1.2.8，协议仍为 8。测试不改原整合包或原存档，不覆盖 Release。更换时客户端和服务端使用相同文件，不并装两份。

## 变更与边界

- Lootr 自动收取只调用个人库存，不启动衰减或刷新，不删除箱体或矿车，不动共享 Lock。关闭「上锁战利品」时仍需原版钥匙。自然转换前保留原战利品表；转换由 Lootr 负责。结构复查不申请额外区块票据，有等待项不会记为自动成功。
- 登神者和涟漪之篇本地实例没有开启 Lootr 衰减，不能把玩家反馈的方块替换归因于衰减。Forge Lootr 1.20 的这个衰减分支是拆除方块，不会放置原版箱。
- Inventory Pets 2.2.8 在真实末地空间地牢箱里放置 `Rebecca` 占位物。磁铁只对符合模板标记、且能从已加载区块核实结构记录的箱子调用原生生成。未验证版本仍保护识别到的占位物，不尝试还原已被旧版取走占位物的箱子。
- 最近获取页的 Shift 提示来自原生物品提示事件。无须改存档或网络协议，也不会展示历史中没有保存的第三方 NBT。

### 远古城市：以服务端方块 ID 复核

用发布版与修订版 JAR、Forge 47.2.18、种子 `81933858` 对照。两只箱子均由实际结构生成，未手动设置其方块、战利品表或物品。测试脚本只负责在需要时让邻近区块就绪、调用正式 JAR 的库存入口和转移方法，并记录方块 ID、方块实体和 Lootr UUID。

| 样本 | 发布 1.2.8 | 修订 1.2.8 |
|---|---|---|
| `3061,-50,2462`，扫描前还是 `minecraft:chest`，有 `minecraft:chests/ancient_city` | 先接收 43 件，原战利品表随即清空；邻近区块就绪后仍为 `minecraft:chest`。 | 转换前接收 0 件、保留战利品表；邻近区块就绪后由 Lootr 转成 `lootr:lootr_chest`。 |
| `3060,-44,2499`，扫描前已经是 `lootr:lootr_chest` | 正常收到物品，当场和 60 tick 后方块 ID、方块实体未变；测试专门允许衰减时会启动 6000 tick 计时。 | 正常收到物品，方块 ID、实体与 Lootr UUID 保持；同样的测试设置下不启动衰减。 |

表内物品数来自 Lootr 0.7.35.93；两次试验独立生成个人库存，只核对各自实际到账，不比较随机战利品数量。Lootr 0.7.35.94 重跑得到相同的方块 ID、战利品表和衰减结论，额外调用了正式代码的收尾分支。**已复现的是“提前取走，导致原版箱从未转成 Lootr 箱”，不是“确认已是 Lootr 的箱变成原版箱”。** 后者在两组隔离环境均未复现，不把前者当作玩家原存档的确定归因。未修改任何原存档，也不自动补发已被取走的战利品。

## 查箱原型初筛（不进入生产 JAR）

隔离 Forge 服务端、Java 17，读真实分节与加载状态。每个热点预热后测 5 组交错重复，表为每组 p95 的中位数。分节命中使用钻石块作为测试标记，不改生产特殊方块定义。

| 热点 | 原路径 | 原型 | 说明 |
|---|---:|---:|---|
| 稀疏附近，未命中调色板 | 0.20 µs | 0.20 µs | 原扫描本已跳过分节，原型没有稳定收益。 |
| 分节命中，最多 512 次检查 | 20.3 µs | 13.0 µs | 仅有命中分节的局部收益。 |
| 96 个分段，128 个点位 | 67.3 µs | 2.3 µs | 不含建位图；附近扫描不走此路径。 |
| 225 个区块的就绪选择 | 45.1 µs | 4.2 µs | 该队列实测只查询了 1 个区块（原路径 225 个）；附近扫描不走此路径。 |

各原型结果与原路径一致。稀疏附近没有候选能覆盖原型的收益条件，初筛不进入正式双 JAR 四场景 A/B。未测得整体收取时间、客户端帧时间或内存改善，**保留原查箱算法，不宣称提速**。

复现入口：`scripts/qa128.py`（`lootr`、`legacy`、`mirage`、`ancient-baseline`、`ancient`、`pets-baseline`、`pets`、`ui`、`minimal`、`quark`、`repair-screen`）。使用 `-Pverification` 另建 QA 辅助模组，正式磁铁 JAR 不含 QA 类。远古城市对照可用 `--lootr` 指定实际的 Lootr JAR。
