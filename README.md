# 宝箱磁铁 · Forge 1.20.1 · 1.1.0

## 安装
将 `dist/chestmagnet-forge-1.20.1-1.1.0.jar` 放入整合包的 `mods`。多人游戏需客户端和服务器都安装。工程未自动修改你的整合包或存档。建议首次在存档副本试用。

**注意：默认会收取自己家里普通储物箱的东西。回家前关闭磁铁，或先排除储物箱。背包开启销毁升级时，符合升级规则的战利品会被销毁，这是预期行为。**

## 操作
- 放在主物品栏、快捷栏或副手，开启后自动工作；包中包里的磁铁不工作。
- 手持磁铁普通右键：开／关，快捷栏上方显示状态与模式。右键方块或矿车不会同时开箱。
- 手持磁铁潜行＋左键空气：打开配置。挖方块、打实体不会打开配置。
- 潜行＋右键储物箱或储物矿车：排除／取消排除；排除操作不改变磁铁启停状态。
- 配置中可选择物品栏、RS、背包，修改三个方向的半径、管理排除列表。
- 默认半径 X=8、Y=3、Z=8，最终尺寸 17×7×17；范围包含端点，以人物所在方块为中心。只访问已加载区块。
- 多个已开启磁铁只让槽位顺序最前的一个工作，副手排在主物品栏后。

## 储存规则
物品栏只写入人物 36 格，不动装备或副手。背包按 Curios→胸甲→副手→主栏顺序填充，遵守输入过滤、压缩、套娃、销毁升级。界面“已处理”包含被背包升级销毁或压缩的物品，不等于原样存储数量。

RS 读取主物品栏／副手的已绑定无线网格，包括 RS Addons 无线合成网格，检查无线覆盖、能量和 INSERT 权限；失败不回退其他目的地。控制器未加载时不会强加载。直接接入目标网络的来源箱子会被跳过。

支持箱子、陷阱箱、木桶、潜影盒、Forge 储物标签容器、运输矿车、漏斗矿车及 Lootr 箱子／运输矿车。不支持任意机器、马匹、第三方库存代理或第三方领地保护的通用适配。

Lootr 按当前玩家的个人战利品处理，无需第一次手动开箱。磁铁不执行破坏箱子／删除矿车的衰减分支，但不会禁止 Lootr 或其他模组自己执行的世界生命周期。已经排除的 Lootr 来源不会被磁铁生成战利品。

方块排除按维度和位置保存（同一位置换箱子仍排除）；双箱整体处理。矿车排除按 UUID 跟随实体，列表中的坐标是添加时记录的位置。磁铁转交他人时设置、排除列表一并保留。

## 配置与恢复
每存档 `serverconfig/chestmagnet-server.toml` 控制范围上限、排除上限、扫描/槽位/栈预算。默认全局 2000 微秒是软预算，不会强行中断其他模组的单次库存调用，不能保证零卡顿。

正常执行意外产生的拒收余量会先退回原槽，失败进入磁铁 NBT 恢复缓存并暂停，可在设置中取回人物物品栏。若其他模组在接收过程中抛异常，标记 `RecoveryUncertain` 并禁止直接取回，以免重复物品；需先核对来源和目标，再由管理员处理缓存。不承诺跨模组库存的断电/崩溃原子事务。

## 从源码构建
需要 JDK 17。先把整合包已有依赖复制进忽略的 `libs`：
```powershell
.\prepare-dependencies.ps1 -PackDir '你的整合包版本目录'
.\gradlew.bat clean dist
```
依赖版本、输出目录与配方均在项目中固定，不需修改原模组源码。

必要自动测试：`./gradlew.bat runGameTestServer -Pverification`。无可选模组运行：追加 `-Pminimal`。测试源码和结构仅在 `-Pverification` 时加入，不打入正常成品。可选 `-PclientSmoke` 自动客户端截图仅限验证工程，要求已有独立 `run/saves/MagnetSmoke` 测试世界。

见 `TESTING.md` 了解已完成和未完成的验证，勿把接口静态核对当成所有实际玩法都已通过。

## 1.1.0：探险者指南针联动
配套安装 `ExplorersCompassUnified-1.20.1-forge-1.3.4.jar`（替换旧探险者指南针，**不要同装旧版**），客户端与服务器同步更新两个 JAR。生物指南针无需升级。缺少指南针或仍用旧版时普通磁铁不受影响，结构联动提示升级并重新搜索。

用新版探险者指南针搜索建筑，成功后可收起指南针。手持磁铁 **Ctrl＋右键**查看当前建筑并确认收取。新搜索、失败、取消、群系/Feature 等非结构结果不能偷偷复用旧建筑；旧版保留结果需要重新搜索。

需在同维度并到建筑主体水平及垂直均不超过32格。扫描区按所有结构片段自动计算 X/Z 外包络，四周统一留16格余量（配置 `structureMargin`），**扫描当前维度全部高度**，不存在沙漠/丛林等按建筑 ID 写死的补格规则。将收取该平面范围内所有可访问储物容器，包括上下重叠建筑或玩家放置的箱子；排除名单始终有效。不会精确追溯箱子的建筑归属。

确认后才可额外加载/生成区块。默认每任务2张票据、全服4张、5tick间隔请求、最多256个区块（配置 `structureChunkLimit`）。超限/超时/满目标明确暂停，不标为完整完成。关闭页面不终止已确认的任务；“取消任务”、离线、换维度、离远、关闭磁铁或重新搜索会停止并清票。满目标后可调整模式，在同一确认页继续；再次 Ctrl右键可重新打开任务。

3D 为当前已加载区域的现场局部方块快照，不是结构原始模板。可拖动旋转、滚轮缩放、输入高度剖切；扫描后“容器楼层”可循环聚焦发现的层。箱子等动态模型用金色方块标记，不读取箱内数据。预览简化、裁剪或剖面高度均不会限制全高度收取。截图中的模型含自然地形，不能据此认定精确建筑归属。

联动自动验收：`./gradlew.bat runGameTestServer -Pverification -PwithCompass`，需将指南针1.3.4副本命名为 `libs/explorer-1.3.4.jar`。原生渲染快照验收使用 `-PrenderSmoke`（自然结构测试先生成 `run/structure-preview.nbt`）。验证源码与测试维度不进入正式 JAR。
