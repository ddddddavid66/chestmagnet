# 宝箱磁铁 1.2.7

Forge 1.20.1 模组，最低 Forge `47.2.18`，需要 Java 17。保留已有建筑指南针、Goety 容器和幸运值兼容。

## 安装

用发行包内的 `chestmagnet-forge-1.20.1-1.2.7.jar` 替换客户端和服务器 `mods` 中的旧版磁铁 JAR。不要同时安装两个版本。上一版可从 [1.2.6 发布页](https://github.com/ddddddavid66/chestmagnet/releases/tag/v1.2.6) 获取。

可选依赖会按运行时是否存在自动启用：Explorer's Compass、Lootr、精妙背包、精妙核心、Refined Storage、RS Addons、Curios。依赖的实测配对见 [1.2.5 测试与兼容记录](docs/测试记录-1.2.5.md)。

## 1.2.7 变更

- 修复磁铁的 FTB 检测：按卷轴身份区分 Tetra 卷轴；RS 和超越维度支持可解析的 Item Filters 标签与 OR 任务；分批检查库存变体和套娃背包。不改原任务配置，不回退已经获得的进度。
- 「最近获取物品」记录最近 96 条实际接收，支持分类、翻页和附魔悬停。背包记录的是「已处理」，包括压缩和销毁，**不是实时库存，也不会用于 FTB 计数**。
- 「上锁战利品」「展示框物品」移到「范围」页的「应用范围」下方。联机协议更新为 7，客户端与服务端均需更新；指南针继续使用 1.3.4。

[1.2.7 实测记录](docs/测试记录-1.2.7.md)

## 1.2.6 变更

- 新增「超越维度」目的地。先在超越维度中选定有权访问的主网络，再切换磁铁的吸收模式。不需要便携终端。
- 「让任务可以检测吸收的物品」默认开启。磁铁放在人物物品栏、快捷栏或副手就可检测，无需正在收取。支持精妙背包、已连接的 RS 和超越维度主网络已有的库存，只推进普通持有型 FTB 物品任务，不消耗物品。各目的地分开统计，不把相互桥接的库存相加。
- 关闭磁铁吸附不会停止任务检测。只有移走磁铁，或关闭「让任务可以检测吸收的物品」，才停止磁铁的检测，不撤销已有进度。携带多枚时，有任一枚开启任务检测即可。共振存储等模组自身的检测不受这个开关控制。
- 绯红教堂只在指南针联动的自动结构任务中额外收取原生预置祭坛基座上的奖励，不收黑暗祭坛本体，也不会收玩家另放的基座。
- 联机协议更新为 6，客户端和服务端都需更新磁铁。指南针仍可用 1.3.4。

支持的可选模组版本、测试场景和开销见 [1.2.6 测试记录](docs/测试记录-1.2.6.md)。

## 1.2.5 变更

- 跨维度存入时，维度卡装在**终端所绑定网络的无线访问点**，不是终端本身。无限范围卡不能代替维度卡；控制器和无线访问点仍须已加载、启用。
- 背包模式检查主物品栏和快捷栏全部 36 槽，保留穿戴和功能槽优先级。前一包只接收部分、已满或过滤拒绝时，余量交给下一包。销毁升级照常生效，物品不会再交给下一包。
- 附近收取优先检查近处已加载区块，普通容器和特殊方块的扫描不再互相阻塞。指南针结构范围及默认性能预算不变。
- 配方上方材料为红石粉，下方仍是紫水晶碎片。
- 兼容较旧依赖不代表现有世界可以直接降级：旧精妙背包可能没有存档已使用的物品或升级，请先完整备份，仅在副本验证。

## 1.2.4 变更

- RS 无线终端支持 Curios 功能槽；依次检查物品栏、副手、饰品槽，跳过未绑定、没电等不可用终端。
- 普通收取和建筑任务仅在有待交付物品或有效来源时解析 RS 目标，减少空闲查询；防回流集合按需构建。
- Forge 最低版本降至 `47.4.10`。
- 配方上方材料改为普通指南针，下方改为紫水晶碎片，其余位置和产量不变。

归墟盘持续存入对照中，旧版和新版各 20 次打开、5 次磁盘重挂载均未观察到空列表；本版本不宣称已修复该间歇问题。详细结果及未完成项见 [测试记录](docs/测试记录-1.2.4.md)，操作见 [使用说明](docs/使用说明-1.2.4.md)。

## 1.2.3 变更

- 指南针结果由磁铁内部统一接入，支持 Explorer's Compass 1.4.0、Unified 1.3.3、1.3.4 API、整合包 Unified 1.2.6；未安装指南针时不加载适配。
- 新增 `StructureTargetProvider` 注册接口。未知指南针不会根据附近建筑猜测；生物群系等非建筑结果不会触发结构收取。
- 支持 Goety: Revelation 的 `lofty_chest`、`crypt_chest`、`pithos`，以及酿造台。带锁容器仍由“收取带锁容器”开关控制，库存收完后才清理锁状态。
- 战利品使用真实服务端玩家和原生解包流程，已生成库存不重新抽奖，幸运值和数据包修改保持原版链路。

完整操作说明见 `docs/使用说明-1.2.3.md`，测试边界见 `docs/测试记录-1.2.3.md`。
